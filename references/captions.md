# Captions and graphics

Approve or verify transcript before animation when the user requests that gate. Keep uncertain speech marked rather than invent wording. Preserve exact approved Roman transliteration; do not add translation or silently correct another language. Word-level timing from ASR needs listening checks, particularly mixed-language speech.

Use actual current timeline audio rather than an earlier assembly. Account for cuts, retimes and source offsets. Keep each completed phrase readable, use sensible line breaks, and avoid outgoing words lingering underneath the next phrase.

For native editability, prefer real transparent titles/Text+ or correctly constructed editable compositions. Do not use repeated opaque footage as caption carriers. Verify alpha and completed phrases before applying a design throughout.

When specified, use Inter Black, consistent white text size and a fixed 1.25x size for yellow emphasis. Do not independently shrink each phrase. Reflow long phrases sensibly while respecting speech timing and readability. Centre within the user-designated guide region; this does not mean the centre of the full frame. Include animation extrema, shadows and ascenders in boundary checks. These settings are user defaults, not a universal design rule.

For Remotion, load installed remotion-captions and remotion-markup guidance when available. Confirm Node/Remotion/browser runtime separately from installed skill files. Use approved text and timing data to build custom graphics. A transparent ProRes 4444 layer may be imported into Resolve, but its text is edited in the Remotion source, not native Resolve Text+. Disclose that tradeoff before substituting it for requested native editability. Verify output alpha in the destination editor. Keep the user's logo/end card unchanged unless requested.
